# To-Do tables — run once in the Supabase SQL editor

Creates the two tables the `/todo` page needs, plus row-level security so a
user only ever sees their own rows. Safe to re-run.

```sql
create table if not exists todo_categories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users on delete cascade,
  name text not null,
  position int not null default 0,
  created_at timestamptz default now()
);

create table if not exists todos (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users on delete cascade,
  category_id uuid references todo_categories on delete cascade,
  text text not null,
  done boolean not null default false,
  due_date date,
  priority boolean not null default false,   -- the favourite star
  created_at timestamptz default now()
);

alter table todo_categories enable row level security;
alter table todos enable row level security;

drop policy if exists "own categories" on todo_categories;
create policy "own categories" on todo_categories
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

drop policy if exists "own todos" on todos;
create policy "own todos" on todos
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

-- Card template per list, and a status per task. Separate statements so this
-- file stays safe to re-run against tables that already exist.
alter table todos add column if not exists status text not null default 'medium';
alter table todos add column if not exists color text not null default 'lilac';
alter table todo_categories add column if not exists pinned boolean not null default false;
alter table todos add column if not exists done_at timestamptz;
```

Deleting a category cascades to its tasks — that is the `on delete cascade` on
`todos.category_id`.

`color` is a palette key (`lilac`, `blue`, `green`, `amber`, `rose`, `slate`),
not a hex value — the app maps it, so the palette can change without a
migration. It lives on the task, chosen from the card itself.

`status` is currently unread by the app — the priority tag it fed was removed.
The column is left in place because dropping it would lose whatever earlier
versions wrote there; nothing depends on its values.

Whether a task is finished is the `done` boolean, with `done_at` stamping when
it happened — set on tick, cleared if the task comes back. The `priority`
boolean is the favourite star.

`pinned` lifts a list to the front of the tab strip. The app caps it at three;
the database does not enforce that, since a cap is a UI rule and a constraint
here would fail a write rather than explain itself.
