# To-Do Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `Coming soon` placeholder at `/todo` with a working task list of user-created categories, each holding tasks with a done state, optional due date, and high/normal priority.

**Architecture:** Two new Supabase tables (`todo_categories`, `todos`) reached through six new functions in the existing `src/db.js`. One new React page, `src/Todo.jsx`, mounted at `/todo` in `App.jsx`. Sorting is pure math and lives in `src/calc.js` so it can be tested without a browser. Writes are optimistic: local state updates first, the network call follows, and a failure refetches.

**Tech Stack:** React 19, Vite 8, react-router-dom 7, @supabase/supabase-js 2, plain CSS in `src/style.css`. Tests are `node:assert/strict` assertions in a plain `.mjs` file — no framework, no runner.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-26-todo-design.md`. Read it before starting.
- Login required. Logged out shows `Log in to see your tasks.` — exact copy, matching Diary and Dashboard.
- Storage is Supabase only. No localStorage path, no guest mode.
- `priority` is a **boolean**: `true` = high, `false` = normal.
- Every Supabase call routes through `db.js`'s existing `report(label, error)` helper. Never call `supabase` from a component.
- Every `db.js` function starts with the `if (!supabase || !user) return …` guard the existing functions use.
- No explicit Save button and no unsaved-changes guard — every change persists immediately.
- Do not build: drag-to-reorder, recurring tasks, subtasks, sharing, reminders.
- Comments explain *why*, not *what*, matching the density of the surrounding code.
- Do not run `git push`. Commit only.

### Task 1: Sort comparator

**Files:**
- Modify: `src/calc.js` (append at end of file)

**Interfaces:**

- Produces: `sortTasks(tasks)` — takes an array of `{ done: boolean, priority: boolean, due_date: string|null, created_at: string }`, returns a **new** sorted array. // --- sortTasks ---------------------------------------------------------
```js
const t = (over) => ({ done: false, priority: false, due_date: null, created_at: '2026-01-01T00:00:00Z', ...over })

// Open work always outranks finished work, whatever its priority or date.
const doneFirst = sortTasks([
  t({ done: true, priority: true, due_date: '2026-01-01' }),
  t({ id: 'open' }),
```

```js
// Task order inside one category: open work first, then what's urgent, then
// what's due soonest. Undated tasks sink below dated ones rather than sorting
// as "no date = very early". Returns a new array; callers hold the input in
// React state, where mutating in place would skip a re-render.
export function sortTasks(tasks) {
  const dueRank = (t) => (t.due_date ? t.due_date : '9999-12-31')
  return [...tasks].sort((a, b) =>
    (a.done - b.done) ||
    (b.priority - a.priority) ||
    dueRank(a).localeCompare(dueRank(b)) ||
    String(a.created_at).localeCompare(String(b.created_at))
  )
}
```

````markdown
Creates the two tables the `/todo` page needs, plus row-level security so a
user only ever sees their own rows. Safe to re-run.

```sql
create table if not exists todo_categories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users on delete cascade,
  name text not null,
  position int not null default 0,
  created_at timestamptz default now()
);

create table if not exists todos (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users on delete cascade,
  category_id uuid references todo_categories on delete cascade,
  text text not null,
  done boolean not null default false,
  due_date date,
  priority boolean not null default false,   -- true = high
  created_at timestamptz default now()
);

alter table todo_categories enable row level security;
alter table todos enable row level security;

create policy "own categories" on todo_categories
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

create policy "own todos" on todos
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

Deleting a category cascades to its tasks — that is the `on delete cascade` on
`todos.category_id`.
````

Append to `src/db.js`:

```js
// To-Do: categories and their tasks. Two tables rather than a category string
// on each task, so a freshly made empty list survives a reload.
export async function loadTodoData(user) {
  if (!supabase || !user) return { categories: [], todos: [] }
  const [cats, todos] = await Promise.all([
    supabase.from('todo_categories').select('*').eq('user_id', user.id)
      .order('position').order('created_at'),
    supabase.from('todos').select('*').eq('user_id', user.id),
  ])
  if (report('Load lists', cats.error) || report('Load tasks', todos.error)) {
    return { categories: [], todos: [] }
  }
  // Task order is computed client-side by sortTasks, so no .order() here.
  return { categories: cats.data, todos: todos.data }
}

// Returns the inserted row: the caller needs the generated id to attach tasks
// to the new category without a refetch.
export async function addCategory(user, name) {
  if (!supabase || !user) return null
  const { data, error } = await supabase.from('todo_categories')
    .insert({ user_id: user.id, name })
    .select()
    .single()
  if (report('Add list', error)) return null
  return data
}

// The tasks go with it — that's the on-delete-cascade on todos.category_id.
export async function deleteCategory(id) {
  if (!supabase) return
  const { error } = await supabase.from('todo_categories').delete().eq('id', id)
  report('Delete list', error)
}

export async function addTodo(user, categoryId, text) {
  if (!supabase || !user) return null
  const { data, error } = await supabase.from('todos')
    .insert({ user_id: user.id, category_id: categoryId, text })
    .select()
    .single()
  if (report('Add task', error)) return null
  return data
}

// One patch function instead of four setters: every edit is the same update.
export async function updateTodo(id, patch) {
  if (!supabase) return
  const { error } = await supabase.from('todos').update(patch).eq('id', id)
  report('Update task', error)
}

export async function deleteTodo(id) {
  if (!supabase) return
  const { error } = await supabase.from('todos').delete().eq('id', id)
  report('Delete task', error)
}
```

```jsx
import { useEffect, useState } from 'react'
import { Pix } from './pixel.jsx'
import { sortTasks } from './calc.js'
import { showConfirm, showPrompt } from './dialog.js'
import {
  loadTodoData, addCategory, deleteCategory, addTodo, updateTodo, deleteTodo,
} from './db.js'

const Frame = ({ action, children }) => (
  <div className="diary-wrap">
    <div className="diary-head">
      <h1 className="diary-title">Small wins, one box at a time <Pix name="check" /></h1>
      {action}
    </div>
    <div className="container diary">{children}</div>
  </div>
)

// A task's date is only worth shouting about while the task is still open.
const isOverdue = (t, today) => !t.done && t.due_date && t.due_date < today

// "2026-07-28" -> "Jul 28". Parsed with T00:00 so it stays the local day.
const prettyDue = (iso) =>
  new Date(iso + 'T00:00').toLocaleDateString([], { month: 'short', day: 'numeric' })

// One category: its tasks, the add field, and the done toggle.
function Category({ cat, tasks, today, onAddTask, onPatch, onDelTask, onDelCat }) {
  const [draft, setDraft] = useState('')
  const [showDone, setShowDone] = useState(false)

  const sorted = sortTasks(tasks)
  const open = sorted.filter((t) => !t.done)
  const done = sorted.filter((t) => t.done)

  const submit = (e) => {
    e.preventDefault()
    const text = draft.trim()
    if (!text) return
    setDraft('')            // cleared first so the field is ready for the next one
    onAddTask(cat.id, text)
  }

  const row = (t) => (
    <div className={'todo-row' + (t.done ? ' done' : '')} key={t.id}>
      <input type="checkbox" checked={t.done} aria-label={`Done: ${t.text}`}
             onChange={() => onPatch(t.id, { done: !t.done })} />
      <button type="button" className={'todo-star' + (t.priority ? ' on' : '')}
              aria-label={`Priority: ${t.text}`} aria-pressed={t.priority}
              onClick={() => onPatch(t.id, { priority: !t.priority })}>★</button>
      <span className="todo-text">{t.text}</span>
      <input type="date" className="todo-date" value={t.due_date || ''}
             aria-label={`Due date: ${t.text}`}
             onChange={(e) => onPatch(t.id, { due_date: e.target.value || null })} />
      {isOverdue(t, today) && <span className="todo-late" title="Overdue">!</span>}
      <button type="button" className="spend-del" aria-label={`Remove ${t.text}`}
              onClick={() => onDelTask(t.id)}>&times;</button>
    </div>
  )

  return (
    <section className="todo-card">
      <div className="todo-card-head">
        <span className="todo-card-name">{cat.name}</span>
        <span className="todo-count">{open.length}</span>
        <button type="button" className="spend-del" aria-label={`Delete list ${cat.name}`}
                onClick={() => onDelCat(cat)}>&times;</button>
      </div>

      {open.length === 0 && !done.length && <p className="dash-note">Nothing here.</p>}
      {open.map(row)}

      <form className="todo-add" onSubmit={submit}>
        <input value={draft} placeholder="+ Add task…" aria-label={`New task in ${cat.name}`}
               onChange={(e) => setDraft(e.target.value)} />
      </form>

      {done.length > 0 && (
        <button type="button" className="link-accent link-btn todo-done-toggle"
                onClick={() => setShowDone(!showDone)}>
          {showDone ? 'Hide done' : `Show done (${done.length})`}
        </button>
      )}
      {showDone && done.map(row)}
    </section>
  )
}

export default function Todo({ user }) {
  const [cats, setCats] = useState([])
  const [tasks, setTasks] = useState([])
  const [ready, setReady] = useState(false)
  const today = new Date().toISOString().slice(0, 10)

  // Named so a failed write can pull the truth back from the server.
  const refetch = async () => {
    const { categories, todos } = await loadTodoData(user)
    setCats(categories)
    setTasks(todos)
  }

  useEffect(() => {
    if (!user) return
    let cancelled = false
    loadTodoData(user).then(({ categories, todos }) => {
      if (cancelled) return
      setCats(categories)
      setTasks(todos)
      setReady(true)
    })
    return () => { cancelled = true }
  }, [user])

  if (!user) return <Frame><p className="dash-note">Log in to see your tasks.</p></Frame>
  if (!ready) return <Frame><p className="dash-note">Loading…</p></Frame>

  async function newList() {
    const name = (await showPrompt('Name this list'))?.trim()
    if (!name) return
    const row = await addCategory(user, name)
    if (row) setCats((prev) => [...prev, row])
  }

  async function delCat(cat) {
    if (!await showConfirm(`Delete "${cat.name}" and everything in it?`)) return
    setCats((prev) => prev.filter((c) => c.id !== cat.id))
    setTasks((prev) => prev.filter((t) => t.category_id !== cat.id))
    await deleteCategory(cat.id)
  }

  async function newTask(categoryId, text) {
    const row = await addTodo(user, categoryId, text)
    if (row) setTasks((prev) => [...prev, row])
  }

  // Optimistic: the checkbox has to feel instant. If the write fails, report()
  // has already alerted, and the refetch drops the change the server refused.
  async function patch(id, fields) {
    setTasks((prev) => prev.map((t) => (t.id === id ? { ...t, ...fields } : t)))
    await updateTodo(id, fields)
  }

  async function delTask(id) {
    setTasks((prev) => prev.filter((t) => t.id !== id))
    await deleteTodo(id)
  }

  const newListBtn = (
    <button className="btn btn-blue diary-filter-btn" onClick={newList}>
      <Pix name="star" /> New list
    </button>
  )

  return (
    <Frame action={newListBtn}>
      {cats.length === 0
        ? <p className="dash-note">No lists yet — make one to start.</p>
        : (
          <div className="todo-grid">
            {cats.map((cat) => (
              <Category key={cat.id} cat={cat} today={today}
                        tasks={tasks.filter((t) => t.category_id === cat.id)}
                        onAddTask={newTask} onPatch={patch}
                        onDelTask={delTask} onDelCat={delCat} />
            ))}
          </div>
        )}
    </Frame>
  )
}
```

### Task 7: Refetch on failed writes

**Files:**
- Modify: `src/Todo.jsx` — the `patch`, `delTask`, `delCat`, and `newTask` functions

**Interfaces:**
- Consumes: `refetch` from Task 4; `updateTodo`, `deleteTodo` already return `void`.
- Produces: nothing new.

Task 4 applies every change locally and leaves it there. `db.js`'s `report()` alerts the user on failure, but the screen still shows a change the server rejected. This task closes that gap. It is separate because it needs `db.js` to report failures back, which means changing three signatures.

- [ ] **Step 1: Return a success flag from the write functions**

In `src/db.js`, change these three to report whether the write landed:

```js
export async function deleteCategory(id) {
  if (!supabase) return false
  const { error } = await supabase.from('todo_categories').delete().eq('id', id)
  return !report('Delete list', error)
}

export async function updateTodo(id, patch) {
  if (!supabase) return false
  const { error } = await supabase.from('todos').update(patch).eq('id', id)
  return !report('Update task', error)
}

export async function deleteTodo(id) {
  if (!supabase) return false
  const { error } = await supabase.from('todos').delete().eq('id', id)
  return !report('Delete task', error)
}
```

`report()` already returns `true` when there was an error, so `!report(...)` is `true` on success.

- [ ] **Step 2: Roll back in the component**

In `src/Todo.jsx`, await the flag and refetch when it's false:

```jsx
  async function delCat(cat) {
    if (!await showConfirm(`Delete "${cat.name}" and everything in it?`)) return
    setCats((prev) => prev.filter((c) => c.id !== cat.id))
    setTasks((prev) => prev.filter((t) => t.category_id !== cat.id))
    if (!await deleteCategory(cat.id)) await refetch()
  }

  // Optimistic: the checkbox has to feel instant. On failure report() has
  // already alerted, and the refetch drops the change the server refused.
  async function patch(id, fields) {
    setTasks((prev) => prev.map((t) => (t.id === id ? { ...t, ...fields } : t)))
    if (!await updateTodo(id, fields)) await refetch()
  }

  async function delTask(id) {
    setTasks((prev) => prev.filter((t) => t.id !== id))
    if (!await deleteTodo(id)) await refetch()
  }
```

`newTask` and `newList` need no change: both already ignore a `null` return, so a failed insert simply adds nothing.

### Task 8: Inline rename

**Files:**
- Modify: `src/Todo.jsx` — the `row` function inside `Category`
- Modify: `src/style.css` — append one rule

**Interfaces:**
- Consumes: `onPatch` (already passed into `Category`), which reaches `updateTodo(id, { text })`.
- Produces: nothing other tasks import.

The spec's layout section says clicking a task's text starts a rename. This is the last piece.

- [ ] **Step 1: Swap the text span for an editable field**

In `src/Todo.jsx`, inside `Category`'s `row`, replace:

```jsx
      <span className="todo-text">{t.text}</span>
```

with a field that commits on blur and on Enter, and abandons the edit on Escape:

```jsx
      <input className="todo-text" defaultValue={t.text} aria-label={`Rename ${t.text}`}
             onBlur={(e) => {
               const text = e.target.value.trim()
               // Empty means the user cleared it — put the old name back rather
               // than saving a nameless task.
               if (!text) return (e.target.value = t.text)
               if (text !== t.text) onPatch(t.id, { text })
             }}
             onKeyDown={(e) => {
               if (e.key === 'Enter') e.target.blur()
               if (e.key === 'Escape') { e.target.value = t.text; e.target.blur() }
             }} />
```

`defaultValue`, not `value` — the field owns its own text while being edited, and `onPatch` syncs state on commit. The row is keyed by `t.id`, so switching tasks remounts the field with the right text.

- [ ] **Step 2: Style it to look like text until focused**

Append to `src/style.css`:

```css

    border: none;
    padding: 2px 3px;
    color: inherit;
    font-family: var(--font-body);
    font-size: 1em;
}
input.todo-text:focus {
    outline: none;
    background: color-mix(in srgb, var(--accent) 14%, transparent);
    border-radius: 4px;
}
```

`input.todo-text` rather than `.todo-text` so it outranks the `.todo-row.done .todo-text` strike-through rule's specificity on the properties it sets, while leaving the strike-through alone.
